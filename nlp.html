Sentiment Triage Model

Can social posts be auto-sorted into positive/negative/neutral so a brand team only has to review what actually needs a human?

The situation

The source dataset doesn't have a native positive/negative/neutral label — it has 191 granular emotion tags ("euphoria," "melancholy," "boredom"...). A documented heuristic grouped those into three polarity classes before any model saw the data, so the "ground truth" here is itself an approximation.

732 posts, heavily skewed toward positive content (59%). TF-IDF + Logistic Regression was trained to classify polarity from raw text alone.

Key takeaway & action

1

Neutral content doesn't get misread as negative — it gets misread as positive

Of posts actually labeled Neutral, the model calls them Positive 45% of the time and only identifies them correctly 36% of the time — it almost never calls them Negative (18%). Because "Neutral" here is a residual bucket from the heuristic label mapping rather than a clean linguistic class, the model has learned to default ambiguous text toward the majority class.

ActionDon't trust the "Positive" bucket's purity at face value for brand-sentiment reporting — add a manual-review threshold for borderline-confidence positive predictions, since that's exactly where mislabeled neutral content hides and would otherwise make sentiment look more favorable than it is.

Limitations

  • Polarity labels are a documented heuristic grouping of 191 emotion tags, not a native ground-truth sentiment label — results should be read as derived-label text classification, not validated sentiment analysis.
  • 732 rows is a small sample for a 3-class text model; the Neutral class alone has only ~111 examples.
  • No evaluation against out-of-distribution text (e.g. a different platform or language) was performed.
